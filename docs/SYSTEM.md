## 1. ภาพรวมระบบ

ระบบประกอบด้วย 2 โมดูลหลักที่ทำงานแยกจากกัน แต่ใช้ฐานข้อมูลบริษัทและระบบยืนยันตัวตนร่วมกัน

| โมดูล | ขอบเขตงาน |
|---|---|
| **Payroll** | ทะเบียนบริษัท พนักงาน นำเข้าเงินเดือนจาก Excel ออกสลิปเงินเดือน |
| **Asset** | ทะเบียนทรัพย์สิน คำนวณค่าเสื่อมราคา ออกรายงานทรัพย์สิน |

แต่ละบริษัทเลือกเปิดใช้งานโมดูลได้อิสระ บริษัทหนึ่งอาจใช้เฉพาะ Payroll เฉพาะ Asset หรือใช้ทั้งสองก็ได้

## 2. โครงสร้างการใช้งานและสิทธิ์

### 2.1 ส่วนงาน 3 ส่วน

| ส่วนงาน | เส้นทาง | ผู้ใช้งาน |
|---|---|---|
| ผู้ดูแลระบบ | `/admin` | ADMIN, HR |
| พนักงาน | `/employee` | USER |
| ทรัพย์สิน | `/asset` | ASSET |

ทั้งสามส่วนใช้หน้าเข้าสู่ระบบเดียวกันที่ `/employee/login` ระบบจะพาไปยังส่วนงานที่ถูกต้องตามสิทธิ์โดยอัตโนมัติ ส่วนทรัพย์สินใช้รูปแบบหน้าจอเดียวกับส่วนพนักงานเพื่อความคุ้นเคย แต่แยกเมนูและข้อมูลออกจากกันโดยสมบูรณ์

### 2.2 สิทธิ์ผู้ใช้งาน

| สิทธิ์ | ขอบเขต |
|---|---|
| **ADMIN** | เข้าถึงและแก้ไขได้ทุกบริษัท ทุกโมดูล เป็นผู้กำหนดสิทธิ์ให้ผู้อื่น |
| **HR** | จัดการพนักงานและเงินเดือนเฉพาะบริษัทในเครือของตน ไม่มีสิทธิ์เข้าถึงโมดูลทรัพย์สิน |
| **USER** | ดูสลิปเงินเดือนของตนเองเท่านั้น |
| **ASSET** | จัดการทรัพย์สินเฉพาะบริษัทที่ได้รับสิทธิ์ ไม่เกี่ยวข้องกับข้อมูลเงินเดือน |

### 2.3 ขอบเขตการมองเห็นข้อมูลของ HR

ยึดตามโครงสร้างเครือบริษัท

- HR สังกัด**บริษัทแม่** เห็นข้อมูลบริษัทแม่และบริษัทลูกทั้งหมดในเครือ
- HR สังกัด**บริษัทลูก** เห็นเฉพาะบริษัทของตนเท่านั้น ไม่เห็นบริษัทพี่น้อง

### 2.4 การป้องกันการเข้าถึงข้าม

ระบบตรวจสอบสิทธิ์ 3 ชั้นเพื่อไม่ให้ผู้ใช้เห็นข้อมูลข้ามขอบเขต

1. **ซ่อนเมนู** ตามสิทธิ์และโมดูลที่บริษัทเปิดใช้
2. **Middleware** ดักเส้นทางที่ไม่มีสิทธิ์ แม้พิมพ์ URL เข้าตรง
3. **API** ตรวจสอบสิทธิ์และกรองข้อมูลตามขอบเขตทุกครั้งที่เรียก

การกรองที่ชั้น API เป็นด่านสำคัญที่สุด เพราะการซ่อนเมนูอย่างเดียวไม่สามารถกันการเรียก API โดยตรงได้

## 3. ระบบเงินเดือน (Payroll)

### 3.1 ทะเบียนบริษัท

รองรับโครงสร้างบริษัทแม่และบริษัทลูก 2 ระดับ บันทึกชื่อบริษัท เลขทะเบียน โลโก้ ที่อยู่ และรายละเอียด

**การระงับการใช้งาน** เปลี่ยนสถานะบริษัทเป็นระงับได้โดยไม่ลบข้อมูล

**การลบบริษัท** เป็นการลบถาวรที่กู้คืนไม่ได้ ระบบจึงกำหนดเงื่อนไขไว้

- ต้องเป็น ADMIN เท่านั้น
- ต้องพิมพ์ชื่อบริษัทยืนยันก่อนลบ
- บริษัทแม่ที่ยังมีบริษัทลูกสังกัดอยู่จะลบไม่ได้ ต้องลบบริษัทลูกให้หมดก่อน
- เมื่อลบ ระบบจะลบข้อมูลที่เกี่ยวข้องทั้งหมดในคราวเดียว ได้แก่ พนักงานพร้อมบัญชีเข้าใช้งาน ประวัติเงินเดือน ประวัตินำเข้า และทะเบียนทรัพย์สินของบริษัทนั้น

### 3.2 ทะเบียนพนักงาน

บันทึกข้อมูลพนักงาน ตำแหน่ง แผนก วันเริ่มงาน อีเมล พร้อมสร้างบัญชีเข้าใช้งานระบบไปในคราวเดียว

ตัวเลือกสิทธิ์ที่กำหนดให้พนักงานได้จะขึ้นอยู่กับโมดูลที่บริษัทนั้นเปิดใช้ และสิทธิ์ ADMIN จะกำหนดได้โดยผู้ที่เป็น ADMIN เท่านั้น

ผู้ใช้ที่ไม่ใช่ ADMIN จะไม่เห็นและไม่สามารถแก้ไขบัญชีระดับ ADMIN ได้

### 3.3 การนำเข้าเงินเดือนจาก Excel

ขั้นตอนการทำงานแบ่งเป็น 2 ระยะ เพื่อให้ตรวจทานได้ก่อนบันทึกจริง

**ระยะที่ 1 — นำเข้าไฟล์** อัปโหลดไฟล์ Excel ระบุบริษัท เดือน ปี และวันที่จ่าย ระบบอ่านข้อมูลเข้าสู่พื้นที่พักข้อมูล พร้อมตรวจสอบความถูกต้องรายแถวและรายงานแถวที่มีปัญหา

**ระยะที่ 2 — ยืนยันการบันทึก** เมื่อตรวจทานแล้ว จึงยืนยันเพื่อบันทึกลงข้อมูลจริง ระบบประมวลผลแบบแบ่งชุดเพื่อรองรับข้อมูลจำนวนมาก

**หมวดข้อมูลที่รองรับ**

- *รายรับ* — เงินเดือน ค่าโทรศัพท์ ค่าที่พักและเดินทาง ค่าล่วงเวลา โบนัส ค่าที่จอดรถ เบี้ยเลี้ยงและรายการอื่น
- *รายจ่าย* — ภาษี ประกันสังคม กองทุนสำรองเลี้ยงชีพ กองทุนกู้ยืมเพื่อการศึกษา ค่าที่จอดรถ และรายการหักอื่น

### 3.4 ประวัติการนำเข้า

เก็บบันทึกทุกครั้งที่นำเข้าไฟล์ ประกอบด้วยชื่อไฟล์ ผู้นำเข้า วันเวลา จำนวนรายการทั้งหมด จำนวนที่สำเร็จ และจำนวนที่มีปัญหา

### 3.5 สลิปเงินเดือน

พนักงานเข้าดูสลิปของตนเองได้ที่ส่วนพนักงาน กรองตามปีและเดือน และสั่งพิมพ์ในรูปแบบ A4 ได้

ระบบยังรองรับการส่งอีเมลเชิญพนักงานเข้าใช้งานระบบพร้อมชื่อผู้ใช้

## 4. ระบบจัดการทรัพย์สิน (Asset)

### 4.1 ทะเบียนบริษัทฝั่งทรัพย์สิน

ผู้ใช้งานระบบทรัพย์สินสร้างบริษัทของตนเองได้ โดยไม่เกี่ยวข้องกับข้อมูลฝั่งเงินเดือน ระบบจะเปิดใช้งานโมดูลและกำหนดสิทธิ์ให้ผู้สร้างโดยอัตโนมัติ

รองรับโครงสร้างบริษัทแม่และบริษัทลูก 2 ระดับเช่นเดียวกับฝั่งเงินเดือน แต่การให้สิทธิ์เข้าถึงกำหนดแยกรายบริษัท — การเป็นสมาชิกบริษัทแม่ไม่ได้ทำให้เห็นข้อมูลบริษัทลูกโดยอัตโนมัติ

### 4.2 ทะเบียนทรัพย์สิน

บันทึกรหัสทรัพย์สิน ประเภท รายละเอียด ที่ตั้ง ราคาทุน อายุการใช้งาน และวันที่ซื้อ

**อายุการใช้งาน** เลือกจากตัวเลือกมาตรฐาน 3 ปี (33.33% ต่อปี) 5 ปี (20%) 20 ปี (5%) หรือกำหนดอัตราเองได้

**ยอดยกมา** สำหรับทรัพย์สินที่มีอยู่ก่อนเริ่มใช้ระบบ กรอกค่าเสื่อมราคาสะสมพร้อมวันที่อ้างอิงได้ ระบบจะใช้ยอดนี้เป็นฐานคำนวณแทนการคำนวณจากวันที่ซื้อ

**การสร้างหลายรายการพร้อมกัน** ระบุจำนวนที่ต้องการ ระบบรันเลขท้ายรหัสต่อเนื่องให้อัตโนมัติ พร้อมข้ามรหัสที่ถูกใช้งานแล้ว รองรับสูงสุด 50 รายการต่อครั้ง และมีปุ่มทำซ้ำเพื่อคัดลอกข้อมูลจากทรัพย์สินที่มีอยู่

**การค้นหาและกรอง** ค้นหาด้วยรหัสหรือรายละเอียด กรองตามบริษัท ประเภททรัพย์สิน และสถานะ

### 4.3 การคำนวณค่าเสื่อมราคา

คำนวณแบบ**เส้นตรง** ตาม**จำนวนวันใช้งานจริง** บนฐาน **365 วันต่อปี** ทำให้ทรัพย์สินที่ซื้อระหว่างปีได้ค่าเสื่อมราคาตามสัดส่วนวันที่ถือครองจริง

```
อายุการใช้งานทั้งหมด (วัน) = 365 ÷ อัตราค่าเสื่อมราคาต่อปี
ค่าเสื่อมราคาต่อวัน       = ราคาทุน ÷ อายุการใช้งานทั้งหมด
ค่าเสื่อมราคาสะสม         = ค่าเสื่อมราคาต่อวัน × จำนวนวันที่ถือครอง
```

**มูลค่าคงเหลือ 1 บาท** ตามธรรมเนียมการบัญชีไทย ค่าเสื่อมราคาสะสมสูงสุดถูกจำกัดไว้ที่ (ราคาทุน − 1 บาท) เมื่อคำนวณจนเต็มจำนวน มูลค่าทางบัญชีจะคงเหลือ 1 บาท และทรัพย์สินแสดงสถานะ **"หมดอายุ"** โดยอัตโนมัติ

> หลักการนี้ตรงกับไฟล์ทะเบียนทรัพย์สิน (Excel) ต้นฉบับ และผ่านการตรวจสอบเทียบตัวเลขแล้วว่าให้ผลลัพธ์ตรงกันทุกรายการ

### 4.4 ประเภทการคำนวณค่าเสื่อมราคา

ระบบเลือกประเภทให้อัตโนมัติตามเงื่อนไขของทรัพย์สินในแต่ละงวดบัญชี ผู้ใช้ไม่ต้องกรอกเอง เนื่องจากประเภทนี้เปลี่ยนไปตามอายุทรัพย์สินในแต่ละปี

| ประเภท | เงื่อนไข |
|---|---|
| ซื้อระหว่างปี | วันที่ซื้ออยู่ภายในงวดบัญชีนี้ |
| คิดค่าเสื่อมราคาเต็มปี | ถือครองเต็มงวดและยังไม่หมดอายุ |
| ค่าเสื่อมราคาหมดในระหว่างปี | เสื่อมราคาครบพอดีภายในงวดนี้ |
| คิดค่าเสื่อมราคาหมดแล้วตั้งแต่ต้นปี | เสื่อมราคาครบก่อนงวดนี้เริ่ม |

ผู้ดูแลระบบแก้ไขชื่อเรียก เงื่อนไข และสูตรของแต่ละประเภทได้จากหน้าตั้งค่า

ตัวอย่างการเปลี่ยนประเภทของทรัพย์สินอายุ 5 ปีที่ซื้อปี 2569

| งวดบัญชี | ประเภทที่ระบบเลือก |
|---|---|
| 2569 | ซื้อระหว่างปี |
| 2570 – 2573 | คิดค่าเสื่อมราคาเต็มปี |
| 2574 | ค่าเสื่อมราคาหมดในระหว่างปี |
| 2575 เป็นต้นไป | คิดค่าเสื่อมราคาหมดแล้วตั้งแต่ต้นปี |

### 4.5 การปิดงวดบัญชี

งวดบัญชียึดตามปีปฏิทิน (1 มกราคม – 31 ธันวาคม) เสมอ

ระบบปิดงวดของปีที่ผ่านไปแล้วโดยอัตโนมัติเมื่อมีผู้เข้าใช้งานหน้าทะเบียนทรัพย์สินหรือหน้ารายงาน โดยบันทึกยอดค่าเสื่อมราคาสะสมยกไปเป็นประวัติถาวร เพื่อให้ตัวเลขของปีที่ปิดแล้วไม่เปลี่ยนแปลงย้อนหลัง

หากมีการแก้ไขข้อมูลตั้งต้นของทรัพย์สิน (ราคาทุน อัตราค่าเสื่อม วันที่ซื้อ หรือยอดยกมา) ระบบจะล้างประวัติการปิดงวดเดิมและคำนวณใหม่ทั้งหมด เนื่องจากประวัติที่คำนวณจากข้อมูลเดิมย่อมไม่ถูกต้องอีกต่อไป

### 4.6 รายงาน

รายงาน 2 รูปแบบ ส่งออกเป็นไฟล์ Excel ได้ทั้งแบบแยกรายงานและรวมทั้งสองรายงานในไฟล์เดียว

**รายงานสรุปทะเบียนทรัพย์สิน** จัดกลุ่มตามประเภททรัพย์สิน แสดงยอดรวมรายกลุ่มและยอดรวมทั้งหมด

**รายงานข้อมูลทะเบียนทรัพย์สิน** แสดงรายละเอียดรายรายการครบ 14 คอลัมน์ ตั้งแต่รหัสทรัพย์สิน วันที่ซื้อ อายุการใช้งาน ประเภทการคำนวณ ไปจนถึงตัวเลขทางบัญชีทั้งหมด

เลือกดูตามบริษัทและรอบปีบัญชี พร้อมตัวเลือกรวมข้อมูลบริษัทลูกในเครือ

> ไฟล์ Excel ที่ส่งออกบันทึกตัวเลขเป็นชนิดตัวเลขจริง ไม่ใช่ข้อความ จึงนำไปคำนวณหรือทำ Pivot ต่อได้ทันที

### 4.7 ข้อมูลหลัก (Master Data)

ผู้ดูแลระบบจัดการได้จากหน้าตั้งค่า

- **ประเภททรัพย์สิน** เพิ่ม แก้ไข ลบได้ (ลบไม่ได้หากมีทรัพย์สินใช้งานอยู่)
- **ประเภทการคำนวณค่าเสื่อมราคา** แก้ไขชื่อ เงื่อนไข และสูตรได้ โดยเลือกจากชุดเงื่อนไขและสูตรที่ระบบรองรับ
- **การแจ้งเตือนใกล้หมดอายุ** ตั้งจำนวนวันล่วงหน้าได้ (ค่าเริ่มต้น 0 = ไม่แจ้งเตือน)

> ประเภทการคำนวณออกแบบให้เลือกจากชุดเงื่อนไขและสูตรที่ผ่านการทดสอบแล้ว ไม่เปิดให้พิมพ์สูตรอิสระ เพื่อป้องกันไม่ให้สูตรที่ผิดพลาดส่งผลกระทบต่อตัวเลขทางบัญชีในทุกรายงานโดยไม่มีการแจ้งเตือน

## 5. การจัดการโมดูลและสิทธิ์เข้าถึง

### 5.1 การเปิดใช้งานโมดูลระดับบริษัท

ผู้ดูแลระบบกำหนดจากหน้าจัดการข้อมูลบริษัทว่าบริษัทใดเปิดใช้โมดูลใด (Payroll / Assessment) หากยกเลิกการเปิดใช้งาน ผู้ใช้ของบริษัทนั้นจะเข้าถึงข้อมูลของโมดูลนั้นไม่ได้ทันที

### 5.2 การให้สิทธิ์รายบุคคลในโมดูลทรัพย์สิน

การเข้าถึงข้อมูลทรัพย์สินต้องผ่านเงื่อนไข **2 ชั้นพร้อมกัน**

1. บริษัทนั้นเปิดใช้งานโมดูลทรัพย์สินแล้ว
2. ผู้ใช้ได้รับสิทธิ์เข้าถึงบริษัทนั้นเป็นรายบุคคล

โครงสร้างนี้ทำให้ระงับบริการทั้งบริษัทได้ในขั้นตอนเดียว โดยไม่ต้องถอนสิทธิ์ผู้ใช้ทีละคน

### 5.3 บัญชีผู้ใช้งานระบบทรัพย์สิน

บัญชีกลุ่มนี้ไม่ผูกกับข้อมูลพนักงาน จึงสร้างจากหน้าจัดการบัญชีทรัพย์สินโดยเฉพาะ ผู้ดูแลระบบเป็นผู้สร้างบัญชี กำหนดสิทธิ์เข้าถึงรายบริษัท ตั้งผู้ดูแลหลักของแต่ละบริษัท เปลี่ยนรหัสผ่าน และเปิดปิดการใช้งานบัญชี

ผู้ใช้หลายคนเข้าถึงบริษัทเดียวกันได้ และผู้ใช้หนึ่งคนดูแลได้หลายบริษัทโดยไม่จำกัดจำนวน

หากลบบัญชีผู้ดูแลหลัก ข้อมูลบริษัทและทรัพย์สินจะไม่ถูกลบตาม แต่บริษัทนั้นจะแสดงสถานะไม่มีผู้ดูแล เพื่อให้ผู้ดูแลระบบโอนสิทธิ์ให้ผู้ใช้คนใหม่

### 5.4 การปิดบริการและล้างข้อมูลทรัพย์สิน

สำหรับกรณีบริษัทเลิกใช้บริการ ผู้ดูแลระบบสั่งล้างข้อมูลทรัพย์สินทั้งหมดของบริษัทได้ ระบบจะแสดงจำนวนรายการที่จะถูกลบให้ตรวจสอบก่อน และต้องพิมพ์ชื่อบริษัทยืนยัน

การล้างข้อมูลนี้**ไม่กระทบข้อมูลพนักงานและเงินเดือน** ของบริษัทเดียวกัน

## 6. โครงสร้างข้อมูล

### 6.1 ข้อมูลร่วม

| ตาราง | หน้าที่ |
|---|---|
| `User` | บัญชีเข้าใช้งานระบบ ชื่อผู้ใช้ รหัสผ่าน สิทธิ์ สถานะ |
| `Company` | ทะเบียนบริษัท รองรับโครงสร้างแม่-ลูก และระบุที่มาว่าสร้างจากฝั่งใด |
| `Module` · `CompanyModule` · `RoleModuleAccess` | การเปิดใช้งานโมดูลของแต่ละบริษัท และสิทธิ์ตามบทบาท |

### 6.2 ฝั่งเงินเดือน

| ตาราง | หน้าที่ |
|---|---|
| `Employee` | ข้อมูลพนักงาน ผูกกับบัญชีผู้ใช้และบริษัทต้นสังกัด |
| `Payroll` · `PayrollItem` | ข้อมูลเงินเดือนรายเดือนและรายการย่อย |
| `PayrollImportBatch` · `PayrollImportRecord` | พื้นที่พักข้อมูลนำเข้าก่อนยืนยันบันทึกจริง |
| `ImportLog` | ประวัติการนำเข้าไฟล์ |

### 6.3 ฝั่งทรัพย์สิน

| ตาราง | หน้าที่ |
|---|---|
| `Asset` | ทะเบียนทรัพย์สิน ราคาทุน อัตราค่าเสื่อม วันที่ซื้อ ยอดยกมา |
| `AssetCategory` | ประเภททรัพย์สิน |
| `DepreciationCalcType` | ประเภทการคำนวณค่าเสื่อมราคา พร้อมเงื่อนไขและสูตร |
| `AssetYearlyClose` | ประวัติการปิดงวดรายปี บันทึกถาวร |
| `AssetCompanyMember` | สิทธิ์เข้าถึงบริษัทรายบุคคลในโมดูลทรัพย์สิน |
| `AssetModuleSettings` | ค่าตั้งค่าระดับโมดูล |

## 7. เทคโนโลยีและการติดตั้ง

### 7.1 เทคโนโลยีที่ใช้

| ส่วน | เทคโนโลยี |
|---|---|
| Framework | Next.js (App Router) |
| ภาษา | TypeScript |
| ฐานข้อมูล | PostgreSQL |
| ORM | Prisma |
| ยืนยันตัวตน | NextAuth (JWT) |
| ส่วนติดต่อผู้ใช้ | Tailwind CSS |
| จัดเก็บไฟล์ | Supabase Storage (โลโก้บริษัท) |
| การติดตั้ง | Vercel |

### 7.2 ตัวแปรสภาพแวดล้อม

| ตัวแปร | ใช้ทำอะไร |
|---|---|
| `DATABASE_URL` | เชื่อมต่อฐานข้อมูลผ่าน connection pool |
| `DIRECT_URL` | เชื่อมต่อฐานข้อมูลโดยตรง สำหรับ migration |
| `NEXTAUTH_URL` | ที่อยู่เว็บไซต์ ต้องตรงกับโดเมนที่ใช้งานจริง |
| `NEXTAUTH_SECRET` | กุญแจเข้ารหัส session |
| `NEXT_PUBLIC_SUPABASE_URL` · `SUPABASE_SERVICE_ROLE_KEY` | เชื่อมต่อพื้นที่จัดเก็บไฟล์ |
| `SETUP_SECRET` | รหัสลับสำหรับเรียกใช้หน้าติดตั้งระบบครั้งแรก |

### 7.3 ข้อควรระวังเมื่อติดตั้งบน Vercel

- **ระยะเวลาประมวลผล** งานที่วนประมวลผลจำนวนมาก เช่น การนำเข้าเงินเดือน กำหนดระยะเวลาสูงสุดไว้ที่ 120 วินาที และแบ่งประมวลผลเป็นชุด
- **ภูมิภาคของเซิร์ฟเวอร์** ควรตั้งให้ตรงกับภูมิภาคของฐานข้อมูลเพื่อลดความหน่วง
- **การตั้งค่าโปรเจกต์** ต้องเลือกรูปแบบโครงการเป็น Next.js ไม่เช่นนั้นเส้นทางทั้งหมดจะเข้าไม่ได้แม้จะสร้างสำเร็จ

### 7.4 การติดตั้งครั้งแรก

1. ตั้งค่าตัวแปรสภาพแวดล้อมให้ครบ
2. รัน `npx prisma migrate deploy` เพื่อสร้างโครงสร้างฐานข้อมูล
3. เรียกหน้าติดตั้งพร้อมรหัสลับเพื่อสร้างบัญชีผู้ดูแลระบบคนแรก
4. เข้าสู่ระบบ สร้างบริษัท และเปิดใช้งานโมดูลที่ต้องการ

### 7.5 รูปแบบการแสดงผล

- **วันที่** แสดงเป็น วว/ดด/ปปปป ตามปีคริสต์ศักราชทั้งระบบ
- **จำนวนเงิน** แสดงทศนิยม 2 ตำแหน่ง พร้อมเครื่องหมายคั่นหลักพัน
